# تعاون — Ta3awen

**الحاجة اللي ما تحتاجهاش، ممكن يحتاجها واحد آخر.**

Ta3awen (تعاون) is a free Algerian mutual-aid Android application: people offer things
they no longer need (clothes, furniture, books, electronics, food, accessibility
equipment …) so another person can benefit from them. Not a marketplace — there is
**no price field anywhere**. This is an ongoing charitable project **in memory of the
author's late mother — رحمها الله**.

The MVP is intentionally simple: a working APK that can be installed and tested on a
real phone, not a production-scale platform.

---

## Tech stack

| Layer | Choice |
|---|---|
| Mobile app | Flutter 3.29 (Dart), Material 3, Arabic RTL, Android-first |
| Auth | Firebase Authentication (email/password) |
| Database | Cloud Firestore |
| Images | Base64 inside Firestore (see "Why not Firebase Storage") |
| Security | Firestore Security Rules (server-enforced, not UI-hiding) |
| Geography | Local static dataset: 58 wilayas + 1527 communes (no maps/API) |

Architecture is exactly: `Flutter → Firebase` with all Firebase-specific code
isolated in `lib/services/` so a future migration (e.g. to Spring Boot + PostgreSQL)
only touches the services layer.

## Project structure

```

  firebase_options.dart  # generated by FlutterFire CLI

```

## How to run (development)

```bash
flutter pub get
flutter run          # device/emulator with USB debugging
```

Requirements: Flutter 3.29, JDK 17, Android SDK 35.

## How to build the APK

```bash
# universal (large)
flutter build apk --release

# recommended: small per-CPU APKs (what was used for the MVP)
flutter build apk --release --split-per-abi \
  --target-platform android-arm64,android-arm \
  --obfuscate --split-debug-info=symbols
```

Output: `build/app/outputs/flutter-apk/`

| File | Size | For |
|---|---|---|
| `app-arm64-v8a-release.apk` | ~10 MB | **almost every modern phone (install this)** |
| `app-armeabi-v7a-release.apk` | ~9.6 MB | older/32-bit-only phones |

Release signing: `android/key/ta3awen-upload.jks` + `android/key.properties`
(password inside `key.properties`). **These are intentionally NOT in git** — keep a
backup somewhere safe; losing them means you can never update the app on Google Play
with the same identity (sideloaded installs are unaffected for private testing).

**Delivery:** the arm64 APK was attached to an email to the project owner and is also
published on the GitHub release: https://github.com/MoIslam-Dev/ta3awen/releases/tag/v0.1.0-mvp

### ⚠️ Manual steps still required (browser, ~2 minutes)

**1. Enable Email/Password sign-in (REQUIRED before anyone can register)**

Firebase refused API-based creation of the auth configuration for new accounts
(`CONFIGURATION_NOT_FOUND` / billing-gated `initializeAuth`), so this must be done
once in the console:

1. Open https://console.firebase.com → project **ta3awen-mvp-5a5ea**
2. **Build → Authentication → Get started**
3. **Sign-in method → Email/Password → Enable → Save**

Verify from a terminal (should return tokens instead of `CONFIGURATION_NOT_FOUND`):

```bash
curl -s -X POST -H "Content-Type: application/json" \
  "https://identitytoolkit.googleapis.com/v1/accounts:signUp?key=$(grep -o "apiKey: '[^']*'" lib/firebase_options.dart | head -1 | cut -d"'" -f2)" \
  -d '{"email":"probe@test.dz","password":"Probe1234!","returnSecureToken":true}'
```

**2. Grant yourself admin (AFTER your first registration)**

1. Register an account in the app (account #1).
2. In Firebase Console → **Firestore → users** → copy the document ID (= your UID).
3. Create collection **`admins`** → document ID = **that UID** → any field (e.g. `role: "admin"`).
4. Restart the app → Profile → "لوحة الإدارة" appears.

Admin docs can only be created from the console — `firestore.rules` blocks clients
from writing `admins/*` (`allow write: if false`).

**3. (Optional, later) Firebase Storage instead of base64 images** — see below.

## Why not Firebase Storage?

New Firebase Storage buckets require the pay-as-you-go **Blaze plan** (card on file),
and the brief for this MVP forbids anything that can cost money. Therefore images are
compressed in-app (≤1000px JPEG) and stored as **base64 inside Firestore**
(`listings/{id}/images/{auto}` docs + one 480px thumbnail in the listing document).
This stays inside the free tier and needs no billing account.

To migrate to Storage later: replace `lib/services/image_service.dart` +
`ListingService.create/update/imagesOf` with Storage uploads — screens/models do not
change (service isolation, section 29 of the brief).

## Data model (Firestore)

```
users/{uid}        fullName, email, wilaya, commune, contactPhone?, disabled, createdAt
admins/{uid}       (existence = admin; console-created only)
listings/{id}      ownerId, ownerName, title, description, category, wilaya,
                   commune, condition, status ('متاح' | 'تم التبرع به'),
                   contactPhone?, image0 (base64 thumb), imageCount (0-5),
                   createdAt, updatedAt
listings/{id}/images/{auto}   index (0-4), data (base64)
reports/{id}       listingId, listingTitle, reporterId, reporterName,
                   reason, description?, createdAt
```

## Security rules (summary)

- `listings`: read requires sign-in; create/update/delete only by the owner
  (validated fields, `ownerId` immutable, status/imageCount constrained) — or admin.
- `users`: you may only create/update your own doc; `disabled` can only be changed
  by an admin; disabled users cannot write listings (rules check `users/{uid}.disabled`).
- `admins`: **clients can never write it** (console/owner-only).
- `reports`: any signed-in user may create (must match their own `reporterId`);
  only admins can read/update/delete.
- No `allow read/write: if true` anywhere. Same rules file covers image sub-docs.

## App features (MVP)

- Register (name, email, password, wilaya → commune) / login / logout / password reset
- Home feed: available listings with image, title, category, wilaya, commune, condition, date
- Search by title + filter by category / wilaya / commune (simple, client-side)
- Listing details: images, info, owner name, optional "reveal contact" button, report
- Create listing: title, description, category, condition, wilaya, commune,
  up to 5 images (compressed), optional contact phone — **no price**
- My Listings: edit / delete / toggle status (متاح ↔ تم التبرع به)
- Admin: view/delete listings, view/dismiss reports, disable users
- Arabic RTL UI, Material 3, loading/empty/error states, user-friendly Arabic errors

## Problems encountered during the build (and resolutions)

1. **Firebase project creation via CLI → 403** (new-account TOS): fixed by creating
   the project in the console.
2. **Auth configuration not API-creatable** → manual console step (see above).
3. **Firebase Storage requires Blaze** → base64-in-Firestore (free), documented above.
4. **Firebase plugin v6/v4 needs a newer Kotlin than Flutter 3.29 ships**
   (`compilerOptions()` missing) → pinned compatible versions:
   `firebase_core ^3.8`, `firebase_auth ^5.3`, `cloud_firestore ^5.4`.
5. **55 MB fat APK** (uncompressed native libs) → `useLegacyPackaging = true`,
   R8 `minify + shrinkResources`, obfuscation + per-ABI split → **10 MB**.
6. `intl` had to be pinned to `^0.19.0` (pinned by `flutter_localizations`).
